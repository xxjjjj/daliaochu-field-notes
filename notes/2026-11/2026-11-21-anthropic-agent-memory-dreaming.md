# Claude 的记忆是怎么设计的：四层结构 + 做梦

## 1. 这是什么

核心事实：Anthropic 把 Agent 记忆拆成"在线抓取（边干边记）+ 离线整合（dreaming，做梦）"两部分，
并用四组公开评估（CL-Bench 1.0 数据库问答、Pokémon Red、35 万文件 wiki 检索、Harvey LAB 合同
生成法律意见书）给出每个组件各自的贡献与失效场景。**这是目前少见的、带数字的自家记忆架构自述。**

## 3. 核心观点（以一手原文为准）

1. **记忆的定义被收窄**：只指"从经验中获得、跨会话保留、以可读上下文形式存下来"的知识。
   明确排除三类：改权重（训练/微调）、单会话内的 in-context learning、以及 compaction（压缩摘要）。
   这样做的好处是——记忆是可审计的文件，不是黑盒。
2. **记忆是一种对未来的预测**。写一条规则，等于预测"这条模式以后还会用到"。写"已验证事实"
   等于预测"未来会话可以不再复核"。所以记忆质量 = 预测质量。
3. **在线抓取（边干边记）**：会话中给显著事件打标签、或写进记忆笔记目录。代价是分散注意力，
   好处是当场抓住。
4. **离线整合（dreaming）**：空闲时重读历史 transcript，纠错、提炼规则、重建表示。理论依据是
   睡眠期海马体回放 → 皮层整合。它可以做五件事：核实纠正笔记、构建新的记忆表示（wiki）、
   把笔记"上浮"进常驻上下文、按目标定向生长、补上单会话看不到的漏洞（跨会话共性/悬空链接）。
5. **四层结构**（视频的归纳，原文未编号，但结构成立）：
   原始记录 transcript（唯一 ground truth）→ 笔记 notes → 知识库/wiki（表示层）→ 上下文必读
   （注入层，越多越糟）。
6. **常驻层必须小，且只当目录**：Claude Code 的 auto memory 只加载 `MEMORY.md` 前 200 行或
   25 KB 作为索引；官方文档明确"指令文件越长，遵守率越低"。
7. **知识库不能替代搜索**：wiki 负责稳定已核验部分，搜索负责时效性；两者互补。
8. **给使用者的三条建议**（第一条是原文原话）：告诉它"记忆是用来干什么的"，但**不要规定怎么记**；
   定期检查笔记、清理错误；按需求组织知识点，不要一视同仁地堆砌。

## 5. 视频 vs 原文：核验与勘误

**成立**：把核心讲成"边干边记 + 做梦"；四层结构方向对；笔记四步（记录错题→分析→核查→沉淀规则）
与原文的 learning loop 一致；"模型越强越应自己判断显著性"是原文结论（提前定规则会削弱效果）；
"笔记可能是错的，必须靠做梦对 transcript 核实"（Mt. Moon 单向台阶案例）；"常驻内容要短、当目录用"；
"整理合同条款 / 补单会话看不到的漏洞"；三个未解决问题（何时写、如何保鲜、如何维持表示成本）——
原文《Thinking backward, looking forward》一节全部覆盖。

**需要打问号的三处**：

1. **"Opus 5 走完四步后得分 0.56 → 0.83"**：原文正文没有这两个数字（应在 Figure 3 图内，无法从文本核对）。
   且原文说的是不同模型成熟度不同，Opus 5 只是第一个"闭环"，四步不是 Opus 5 专属规格。
   **结论：数字待核，不要当官方原文引用。**
2. **"值得记的是自己试错出来的经验，而非所有内容"**：这句话在原文里被实验反向修正了——显式规定
   "只记录失败"，Opus 5 和 Opus 4.7 的性能增益都明显下降。原文的真实口径是"给用途、不给规则，
   让强模型自己判断显著性"。视频把它讲成了"多记无用、只记踩坑"，容易被执行成"只记错题"这条被证伪的策略。
3. **"四层" 是二阶归纳**：原文的层不是整齐编号的四层，而是 transcript / notes / wiki 表示 /
   注入上下文四类角色，且 dreaming 的核心工作之一是**把细节往下层压、只留链接**。照搬"四层"
   做产品设计没问题，但别以为原文给了字段级规格。

## 6. 我学到了什么

- **记忆的载体是文件，不是对话历史。** 跨会话经验不落盘就等于没有；这也是本仓库 `notes/`
  `playbooks/` 存在的理由。
- **不做离线整合的记忆系统会稳定地复用错误。** 在线时写下的是"当时的猜测"，没有回头核实的动作，
  错笔记会被每次会话重新信任。这跟"智能负债 / Skill 半衰期"是同一个病（见 2026-11-19 卡片）。
- **记忆的价值在"屏幕读不到的东西"**：策略、计划、验证过的规则。凡是环境里随时能读到的（当前位置、
  余额、状态字段），写进记忆就是负债——Pokémon 案例里 Sonnet 3.7 的 413 个文件大半是这个。
- **常驻上下文和知识库是两件事**：一个是每次都要付 token 的目录，一个是按需检索的仓库。
  把知识库往提示词里塞，等于用最贵的方式做索引。
- **表示层会反噬**：wiki 的价值在于抽象和链接，膨胀到比原文还大就彻底失效。所以"知识库越大越好"
  是错的。

## 7. 对个人能力 / 企业 AI 落地的价值

1. **给已有 Agent 做体检的四个问题**：经验写进文件了吗？谁负责核实（有没有"做梦"环节）？
   常驻上下文是否只做目录？知识库有没有淘汰机制？——这四问比"要不要上记忆功能"有用得多。
2. **本项目（打捞处仓库 + llm-wiki）恰好是这个架构的自建版**：`notes/` 是笔记层，`llm-wiki`
   知识包是表示层，Skill 是注入层，`playbooks/` 是验证过的方法。原文的价值在于给出了**每层的
   评估指标**（命中率、token 节省、事实覆盖率），可以拿来给自建体系做量化而不是凭感觉。
3. **"错题本"要带状态位**：每条笔记必须能区分"已验证 / 未验证 / 已过期"，否则沉淀越多、
   复用错误越快。这是低成本、可立刻落到现状做法上的一条。
4. **对企业侧的转译**：业务知识库（合同、条款、口径）适合 wiki 化 + 搜索双通道；单文档就能查到的，
   不要建 wiki。这条能直接回答"我们知识库为什么用不起来"。

## 8. 可做的小实验（未执行）

- **A｜错题本加状态位**：给现有笔记/规则加 `verified_at` + `source` 两个字段，季度重跑一次核验，
  统计"过期条目占比"。零算力成本，纯流程。
- **B｜对比"只记错题" vs "自由判断"**：在同一个重复任务上跑两版记忆指令，看第二周成功率。
  这是原文那条反直觉结论的自测，成本一天。
- **C｜小规模 dreaming 试跑**：选一个已有知识包，夜间跑一次"对 transcript 核实笔记"的整理任务，
  记录改动条数与误改条数。**注意**：dreaming 输出对当次会话不可见且要付算力，别做成实时链路。

## 9. 风险和边界

- **成本**：原文自己承认 dreaming 要花算力，"持续核查全部记忆不现实"，现实做法是按"记忆被访问
  频率"调核电节奏。别把做梦做成每小时全量巡检。
- **错误放大**：注入层一旦写错，会被每一次会话信任地读进去；所以注入层的准入门槛要高于知识库。
- **表示膨胀**：wiki 可能长成原文的替身，占用反而更大。
- **厂商叙事风险**：这是 Anthropic 用自家模型跑的自家评估，模板是"能力成熟度递进"（4.6 → 4.7 →
  5 才闭环）。对"换别的模型照抄能不能复现"没有证据，落地前必须自测。
- **口径边界**：0.56 → 0.83 这类图内数字未经文本核实，不对外引用。视频是二创，仅作入口。

## 10. 当前结论

一手源扎实、可引用；视频方向对但有一处被实验证伪的表述（"只记踩坑"）和一处未核实数字。
价值不在"Anthropic 又发了个功能"，而在于它把 Agent 记忆拆成**可分别评估的四类角色 + 一个离线
核实动作**，并且诚实列出了三个还没解决的问题。对本仓库最直接的一条：**给知识条目加时间戳和来源，
把"定期核实"变成动作而不是期望**。
