# Vibecoding 两个核心 Prompt：第一性原理 + 对抗式审查

## 1. 这是什么

AI 自媒体博主「数字生命卡兹克」（X: @Khazix0918）分享的 Vibe Coding（AI 编程）方法论，核心是两个 Prompt 技巧：

1. **第一性原理（First Principles）**：在复杂任务提示词后加一句"请从第一性原理出发"，让 AI 放下经验与现成方案，回到本质重新推导。
2. **对抗式审查（Adversarial Review）**：功能开发完成后，让 Agent 切换身份（开发者 → 测试员/红队），主动寻找边界条件、异常场景和漏洞，可开启多个子 Agent 进行攻防对抗。

## 3. 核心观点 / 核心能力

**技巧一：第一性原理**
- 动机：AI 擅长顺着问题给答案，但"问题本身是否该这样问"没人检查。
- 做法：复杂任务（解决问题、修 BUG、设计架构）在 Prompt 后加"从第一性原理出发"，无需装 Skill、写 System Prompt。
- 案例：AIHOT 连续三天抓不到 OpenAI 官网内容，Agent 第一轮说"把改坏的抓取修回来"；补一句"从第一性原理出发再查一次"，才挖到底层抓取机制本身的问题，不修会反复爆雷。
- 类比：马斯克造火箭不接受"火箭本来就这么贵"的行业共识，从原材料和制造流程重新核算，成本降 90%。

**技巧二：对抗式审查**
- 动机：方案好 ≠ 上线稳，功能完成后仍有漏洞。
- 做法：项目进入测试阶段时，在对话里说"开启对抗式审查"，让 Agent 从开发者切换成专职找 BUG 的测试员/红队，可启动多个子 Agent 与产品攻防对抗。
- 案例：活动报名页面正常测试只测"填姓名手机号→提交成功"；对抗式审查会测手机号空着、提交中断网等异常场景。
- 作者自述不懂代码，靠这两个技巧提升项目上线信心。

**扩展用法（文章版补充）**：写文章让 AI 从逻辑漏洞/事实准确性/论证力度对抗式审查；商业方案用第一性原理剥掉假设直问核心逻辑；人生决策（如换工作）两套思路合用。

## 4. 我学到了什么

- "第一性原理"提示词的本质是**强制 AI 做根因分析**：第一轮修复往往停在表面（症状层），追加这句能让它回到机制层。这与"故障排查要找根因闭环、不能表面修复"的工作标准完全同构，可以沉淀为排障动作。
- 对抗式审查的本质是**用角色切换 + 多 Agent 攻防替代人工测试盲区**：正常路径测试只能覆盖 happy path，红队式审查覆盖异常路径。
- 两个技巧都是"轻量 Prompt 引导"而非新工具，零安装成本，适合推广给不写代码的人使用。

## 5. 它是否可信，哪些需要验证

- 文章/作者/产品均可核验，属于个人实战经验分享，非系统性研究或实证数据。
- "神级""万能"是自媒体话术，需打折看。
- 待验证点：
  - 对复杂任务（如架构设计）"第一性原理"提示词的实际增益幅度，是否受模型能力影响；
  - 多子 Agent 对抗式审查的 token 成本与收益比，在小项目上是否划算；
  - 对简单任务加"第一性原理"是否反而过度复杂化。

## 6. 对个人能力有什么价值

- 可直接套进日常排障与开发：排查问题时先问"从第一性原理出发再查一次"，避免修表面；交付前用"开启对抗式审查"找异常路径漏洞。
- 与 Agent 工作流、脚本维护、内部工具开发场景贴合，属于低成本高复用技巧。

## 7. 对企业 AI 落地有什么价值

- 适合作为**团队内 Vibe Coding / AI 辅助开发的基础方法论**：让不写代码的业务同事也能通过两个 Prompt 提高 AI 产出质量与上线信心。
- 排障场景（如 RPA/自动化流程偶发失败）可借鉴"第一性原理"追问机制层根因，减少"修好了又复发"。
- 多 Agent 攻防可作为交付前质量门禁的补充思路，但需评估成本。

## 8. 可做的小实验

1. 选一个近期"修过又复发"的自动化/抓取/流程问题，用"从第一性原理出发再查一次"重查，对比是否挖到机制层根因。
2. 对一个内部小工具/页面，在对话里"开启对抗式审查"，收集异常路径问题清单，看覆盖了哪些正常测试漏掉的场景。
3. 记录两次实验的 token 消耗与时间成本，验证成本收益比。

## 9. 风险和边界

- "第一性原理"不是万能咒语：对简单任务可能过度设计；对弱模型可能只是换一套话术，未必真做机制层分析。
- 对抗式审查会显著增加 token/调用成本（多子 Agent 攻防），成本敏感场景需设置范围或只对核心功能启用。
- 方法论来自单一个人经验，案例细节未独立验证，效果存在个体差异。
- 不构成对 AIHOT 产品的背书；文中运营数据来自作者自述。

## 10. 当前结论

两个 Prompt 技巧可信、可复用、零安装成本，价值在"根因追问 + 红队审查"两个动作的工程化。建议先做小实验验证成本收益，再把两个动作沉淀进内部排障与交付检查流程。
