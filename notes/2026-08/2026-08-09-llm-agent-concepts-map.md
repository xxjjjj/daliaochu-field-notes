## 3. 核心观点 / 核心能力

可用一句话先建立正确的分层：

- **LLM**：负责理解、生成、判断的概率模型；本身不会持久记住历史，也不天然拥有系统权限。
- **上下文与记忆**：把当前任务有关的规则、历史、资料，以原文、摘要或检索结果重新放进模型输入；“记忆”本质是上下文管理与存储/检索策略，不是模型永久记住了用户。
- **RAG**：先检索外部资料，再把证据片段连同来源交给模型生成。向量检索是常见实现，不是 RAG 的定义，更不等同于“本地搜索”。
- **工具调用 / Function Calling**：模型按结构化约定提出调用意图，运行时负责校验权限、执行工具、回传结果。它是接口模式，不等于 Agent。
- **MCP**：连接 AI 应用与外部数据源、工具和工作流的开放协议；它可标准化接入，但不自动解决鉴权、最小权限、审计、可靠性或业务流程设计。
- **Skill**：面向某类目标的可复用操作说明、约束、脚本和模板的组合。Skill 的具体形态因产品而异，不是一个单一行业标准。
- **Agent**：在目标、状态、工具和执行循环之上进行计划—执行—观察—调整的系统。是否称为 Agent，关键不是“调用了工具”，而是是否具备受控的多步决策与执行闭环。
- **SubAgent**：把任务分解给上下文或权限隔离的专长执行单元；除节省主上下文外，也用于并行、专业分工和风险隔离。

导图的“从能说到能做”主线适合作为入门框架，但不是严格线性技术史：工作流、RAG、MCP、Skill、Agent 能组合，也可以独立存在。

## 4. 我学到了什么

1. 不要按名词采购或搭建。先判定问题属于哪一层：缺知识证据优先知识治理/RAG；缺确定性流程优先工作流/RPA；缺跨系统连接再评估 API/MCP；只有需要多步动态判断时才考虑 Agent。
2. “灵活”不天然优于“刚性”。涉及审批、客户数据变更、财务或对外动作，优先确定性流程、权限边界和人工确认；Agent 适合信息不完整、路径会变化的研究与辅助任务。
3. 对企业可交付的关键不在模型会不会调用工具，而在：数据来源是否可信、操作是否可回滚、权限是否最小化、每一步是否可审计，以及失败时由谁接管。

## 5. 它是否可信，哪些需要验证

**已核验**

- MCP 官方定义是将 AI 应用连接到外部系统的开源标准，覆盖数据源、工具和工作流；官方类比为 AI 应用的 USB-C。
- 视频页面确认了原始标题、作者、发布时间、时长和主题标签。

**需校正或补充**

- “RAG = 搜本地向量数据库”过窄：检索源可以是网页、数据库、关键词索引或混合检索；质量取决于切分、召回、重排、引用和评测链路。
- “MCP = Agent 调用功能的协议”过窄：它是 client/server 的互操作协议，AI 应用未必是 Agent；工具、资源、提示等能力也不等同于自动授权执行。
- “Skill 在 Agent 之上”只是某些产品的架构画法。Skill 也可以封装确定性工作流，未必需要 Agent 或 MCP。
- “OpenClaw”是具体产品/生态名，不应被抽象为普适技术层。若评估其接入，仍需逐项核验代码来源、维护情况、许可证、权限模型、网络暴露、供应链与实际运行成本。

**未完成的核验**

- YouTube 字幕 API 因 IP 限制无法获取完整转录；尚未逐段核对视频原话与导图的对应关系。

## 6. 对个人能力有什么价值

- 面向业务方沟通时，可用“问题—能力层—控制措施”替代堆砌 AI 名词。
- 方案评审可增加四个固定问题：需要什么证据？需要执行什么动作？谁有权限？失败后如何恢复？
- 从会使用工具提升到会设计可运行的业务闭环：输入、判断、行动、留痕、人工兜底和效果指标缺一不可。

## 7. 对企业 AI 落地有什么价值

对 CRM、飞书自动化、RPA 和知识服务，推荐的优先顺序不是“先上 Agent”：

1. 选定单一业务目标（如减少知识查询等待、降低重复录入、提高跟进完整率）；
2. 先治理数据源、字段口径、权限和可追溯证据；
3. 对稳定高频任务先做确定性自动化；
4. 对信息检索型问题引入带引用的 RAG；
5. 对跨系统接入建立 API/MCP 的最小权限、审批和审计；
6. 仅在任务路径不固定且收益足以覆盖评测、监控与人工接管成本时，采用 Agent。

可衡量指标应落在业务侧，例如查询命中率与人工复核率、工单处理时长、数据回填率、异常率、人工接管率，而非工具数量或“是否用了 Agent”。

## 8. 可做的小实验

选一个低风险、只读的内部知识问答场景，进行两周对照：

- 建立 20 个已知标准答案的问题集，保留原始文档链接和版本；
- 用“直接问模型”与“检索后附引用回答”比较正确率、引用可追溯率、人工复核时间；
- 对无证据或低置信度回答强制输出“需人工确认”，不允许自动写入 CRM 或触发外部消息；
- 若检索质量已经不足，再优化知识结构、切分与权限，而不是直接增加 Agent 循环。

## 9. 风险和边界

- **数据与权限**：将内部资料接入 RAG/MCP 前要确认数据分级、租户边界、访问主体与日志；模型能看到不代表有权执行。
- **幻觉与错误执行**：RAG 降低但不消除错误；外部写操作必须设置参数校验、最小权限、审批/确认、幂等与回滚。
- **成本与稳定性**：长上下文、反复检索和多 Agent 循环都会增加时延与成本；先设最大轮次、预算和失败降级策略。
- **供应链**：第三方 Skill/MCP 可能要求敏感凭据、读取本地文件或执行命令。安装前应审查源码、维护状态、权限声明和网络行为，禁止为方便而导出主账号 Cookie 或高权限令牌。
- **版权与公开边界**：本笔记只记录概念和可验证来源，不转载视频画面、逐字稿或群聊截图。

## 10. 当前结论

这是一份适合作为 AI 名词去魅和分层思考的入门材料，最大价值不是记住“RAG/MCP/Skill/Agent”的排序，而是建立选型纪律：**先明确业务问题与风险边界，再选择最小、最可控的技术组合。** 对企业场景，可靠知识、权限审计、确定性流程和人工兜底通常应先于“更自主的 Agent”。
