# BilldDesk——WebRTC 远程桌面，亮点是浏览器主控和高帧率串流

## 1. 这是什么

小红书视频（作者“青青王-AI”）推荐的跨平台远程桌面项目。视频画面中展示的产品名是 **BilldDesk Pro**：手机/浏览器/电脑互为主控被控，支持文件传输、多设备管理、自部署，并实测了 2K@60、2K@120（RTX 5070）、1080P@60 等档位，主打硬件编解码（NVIDIA H264/H265/AV1）、零拷贝、游戏串流。

**审题第一刀：视频标题说“开源项目”，但画面里展示的 BilldDesk Pro 恰恰是不开源、需付费订阅源码的版本。** 这是这条资料最大的误导点，详见第 5、9 节。

> 勘误：同一线索最初误判为 RustDesk（见 2026-09-19-rustdesk 笔记），截图补全后已更正。RustDesk 作为对照项目仍保留在那篇笔记里。

## 2. 原始来源

- 发现入口：小红书 https://xhslink.cn/o/AjeLVyrnPcw（风控无法直读，结论依据晶晶姐提供的截图）

- 移动端：https://github.com/galaxy-s10/billd-desk-flutter
- 技术栈：Vue3 + TypeScript + Node.js + WebRTC + Electron + Flutter，服务端含 Socket.io 信令 + coturn

## 3. 核心观点 / 核心能力（官方 README 口径）

- web 网页可直接作为主控发起远控（电脑端/安卓端），也可被控“仅观看”——**浏览器即客户端，不用装主控软件**，这是它相对 RustDesk/ToDesk 形态上最不一样的点。
- 电脑↔电脑、电脑↔安卓、安卓↔电脑、安卓↔安卓，矩阵齐全（iOS 未见官方支持）。
- 文件传输、多设备管理、自部署（官方鼓励私有化）。
- 高帧率/高码率是明牌卖点：硬件编解码开关、零拷贝、NVIDIA H264/H265/AV1（驱动需 570.0+）、AMD H264/H265，定位包含**游戏串流**，不只是办公远控。
- 开源版（MIT）可免费商用、可私有化；**Pro 版闭源，VIP 包月 6 元/月、包年折合 4.2 元/月；Pro 源码另需订阅购买**。隐私屏、虚拟屏、屏幕墙、批量群控、高码率/帧率/画质等均为 Pro 付费功能。

## 4. GitHub 本体实查事实（非二手宣传）

- ⭐ 7,896 / fork 949 / watch 仅 41 / open issues 5；License **MIT**；主语言 TypeScript；2024-02-27 创建。
- **没有发布过稳定版，GitHub Releases 为空**。
- 官方 README 原话警告：“BilldDesk 目前仍未发布稳定版，**不建议开发者用于生产环境**”；“每次提交都可能不兼容旧版本（破坏性更新）”。
- 作者自述：项目只有**一人开发**，初版是三天做出来的 idea；后把 master 当 dev 直接推，外部人常跑不起来，被吐槽“假开源”。
- 最近一次提交 2026-09-01，仍在维护；但近四条提交信息全是 `docs: readme`，看不到近期代码迭代节奏。

## 5. 信息可信度分层

- **可信（GitHub 官方仓库一手）**：技术栈、开源版 MIT、无稳定版、Pro 闭源付费、功能矩阵、单人维护、破坏性更新声明。
- **厂商/作者自报（待独立验证）**：视频中 2K@120 等帧率实测、硬件兼容性、连接成功率。实测环境全是中高端 N 卡，不等于普通办公本和跨运营商网络的体验。
- **不可信（AI 水文编造）**：搜索中 CSDN 等二手“完全指南”写了企业 RBAC、LDAP/AD 集成、Prometheus/Grafana 监控、2FA CLI 命令、“已帮助 340 家企业”“连接成功率 98.7%”等，**官方仓库均无对应功能或文档**，典型的流量站 AI 拼贴，不能当事实引用。

## 6. 我学到了什么

- “开源项目”四个字要拆开看：开源核心引流 + 闭源 Pro 收费是个人开发者常见的开源商业化路径，**视频拿 Pro 的能力截图配“开源”标题，是这类内容的标准话术**，追一眼仓库 README 的“Pro 不开源”段落就能拆穿。
- 技术上，WebRTC + 浏览器主控是比传统远控更轻的形态：主控零安装，适合临时技术支持、客服远程协助这类“对方点个链接就能被接管/观看”的场景，与我们讨论过的 web 化工具方向一致。
- 高帧率串流（AV1/零拷贝/硬编硬解）这条线和 Moonlight/Parsec 同源，正在下沉到个人项目，说明 WebRTC + Nvenc 方案的工程门槛已经很低。

## 7. 对企业落地有什么价值

- 形态启发大于产品本身：**“浏览器发链接、对方无安装被远程协助”**这个交互值得借鉴，未来 IT 支持/实施远程帮业务同事操作时，免安装主控能降低使用门槛（尤其工厂、海外同事装客户端困难的场景）。
- 但 BilldDesk **当前不满足任何企业生产准入**：无稳定版、单人项目、破坏性更新、无企业管控/审计能力（开源版连后台管理之外的企业能力基本为零）、Pro 是付费闭源且同样来自单人作者。企业远程支持的正经选择仍是 RustDesk 自建（124k stars、AGPL、活跃迭代、Server Pro 有管控台）或商业软件。
- 与本组 RPA/computer-use 议题的关系：它是“人在环里”的远控，不是自动化；但 WebRTC 画面采集 + 浏览器注入输入这套实现，可作为观察 web 端 computer-use 技术栈成熟度的样本。

## 8. 可做的小实验

1. 个人玩：官方下载客户端 + Chrome 当主控，零成本体验“浏览器远控电脑”和局域网游戏串流畅度（注意主控被控版本需一致，官方建议同版本）。
2. 真要评估自部署：按官方文档跑信令 + coturn 中继，重点测跨运营商 P2P 成功率——这是所有 WebRTC 方案的共同命门，帧率数字反而其次。
3. 不建议投入任何生产环境集成或二次开发，直到项目发布稳定版并承诺兼容性。

## 9. 风险和边界

- **宣传误导**：视频标题“开源”与展示对象 Pro 闭源付费不符；高帧率截图来自高配 N 卡单机，不代表网络传输的真实体验。
- **生产风险**：官方自认无稳定版、破坏性更新、单人维护——作者一旦停更或转向，部署方无人兜底。
- **安全风险**：远程桌面 = 交出整台机器。个人项目的安全审计、鉴权强度、连接审计没有经过企业级检验；自部署暴露公网时弱口令/信令鉴权缺陷代价极高。
- **付费可持续性**：Pro 源码订阅模式下，停止付费后源码与升级的连续性要自己承担风险。
- 合规：同所有远控工具，工厂/客户环境安装需安全审批与对方同意。

## 10. 当前结论

BilldDesk 是一个值得**知道和把玩**的个人开源项目：浏览器即主控、高帧率串流两个亮点有启发，MIT 协议友好。但小红书视频把闭源付费的 Pro 当“开源项目”主推、且回避了“无稳定版、单人维护、别上生产”的官方警告，宣传成色要打折。对我们的价值是认知层（看 WebRTC 远控形态的演进），不是工具承载层；企业远程支持场景请走 RustDesk 自建或商业方案。
