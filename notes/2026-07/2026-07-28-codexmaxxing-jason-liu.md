# Codex-maxxing：把单次提示转成可审查的持续工作循环

## 1. 这是什么

Jason Liu 的公开文章与 OpenAI 白皮书讨论一种 Agent 工作方法：不要把 Agent 当作“一问一答”的生成工具，而是为一项工作建立能持续推进的**操作循环**（operating loop）。循环由长期上下文、可执行工具、定时回访、明确验收标准和人工审查组成。

原始资料：

- 文章：[Codex-maxxing — Jason Liu](https://jxnl.co/writing/2026/05/10/codex-maxxing)
- 白皮书：[Codex-maxxing for long-running work（OpenAI PDF）](https://cdn.openai.com/pdf/8a9f00cf-d379-4e20-b06f-dd7ba5196a11/OAI_WhitePaper_Codex-maxxing26.pdf)

## 2. 已核验的核心观点

1. **持久线程**：重要工作应有可反复回到的上下文，而非每次从零说明。长线程有成本，需权衡连续性和费用。
2. **显式记忆**：把人员、项目状态、决策和待办写入可编辑的文件，而不是只留在聊天历史中；用 Git diff 审查记忆变更。
3. **过程内引导**：在 Agent 执行过程中持续补充方向、约束和下一步，避免等整段任务结束才纠偏。
4. **受控自动化**：对变化较慢、可复查的事项设置定时检查，例如发现待处理消息、收集反馈、生成草稿；不可逆动作仍由人确认。
5. **可验证目标**：目标应包含验收条件、约束或测试，而非只写“完成方案”。
6. **产物即协作界面**：文档、表格、网页、代码差异等产物应可直接检查和批注，审查不应脱离实际输出。

## 3. 三层业务价值

### 对业务部门

- **销售与客服**：可用“收集上下文 → 起草建议 → 人工审核发送”的循环提升响应速度，而不让 Agent 擅自对外承诺。
- **运营**：可定期汇总公开反馈、异常和待办，先形成可审查的清单，再决定跟进动作。
- **管理**：让周期性事项沉淀为可追溯的状态、风险和决策记录，减少交接时的信息丢失。

### 对 IT/BP 能力

重点从“写一个更好的提示词”转为设计完整闭环：输入与权限、执行边界、产物位置、验收方式、人工审批、失败后的回退和审计记录。

### 通用认知

真正可持续的 Agent 系统不是无限自主，而是让上下文、行动、复核和学习有明确边界。自动化程度越高，越需要可见的证据和人类决策点。

## 4. 可做的小实验

选一个低风险、可量化的内部任务，运行两周：

- 目标：每个工作日汇总指定来源的待办与风险，并只生成草稿；
- 记忆：将已确认的决策、未决问题和来源链接写入版本控制文件；
- 验收：记录遗漏率、人工修改率、节省时间和错误类型；
- 边界：不自动发送消息、不修改业务数据、不处理含敏感信息的原文；
- 复盘：每周审查差异，删除无价值记忆与失效自动化规则。

## 5. 风险与待验证问题

- **成本与上下文膨胀**：长期线程和频繁轮询会增加费用，需要设置频率、停止条件和预算上限。
- **权限与数据安全**：连接邮箱、IM、日历或业务系统前，必须最小授权、明确数据边界，并保留审计记录。
- **错误累积**：错误摘要或记忆会在后续循环中被放大，因此记忆变更需要可审查、可回滚。
- **自动化越权**：退款、对外回复、数据修改等动作必须保留人工同意，不应因“循环”而自动执行。
- **适用性**：公开案例基于特定产品与工作环境；迁移到其他工具或组织前，需要以小样本实测验证。

## 6. 当前结论

这套方法最值得复用的不是某个具体产品功能，而是“**持续推进 + 明确边界 + 可审查产物 + 人工决策**”的工作设计。适合先从低风险的信息整理、草稿和提醒类任务开始，验证收益后再扩大范围。
