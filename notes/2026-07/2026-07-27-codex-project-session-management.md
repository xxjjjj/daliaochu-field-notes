# Codex 不卡的秘诀：项目文件夹 + 会话隔离 + 记忆文件迁移

## 1. 这是什么

抖音博主「大白AI」的一条 Codex 入门教程，面向小白用户，讲的是 Codex 使用中最常见的两种"卡住"场景——项目混乱和对话过载——以及对应的整理和迁移方法。

视频本身没有展示 Codex 的高级功能或代码实操，核心是一套**使用习惯和工作组织方法**：把项目文件夹当"公司"、把单个对话当"员工"，用"记忆文件"在对话之间传递上下文。

转发中附了许晶晶整理的完整文字摘要，覆盖了基础概念、两种混乱场景和对应解法。

## 3. 核心观点 / 核心能力

视频把 Codex 使用方法归纳为三个层次：

### 基础概念

1. **项目文件夹 = 公司**：不同主题的工作要分项目文件夹管理，不能混在一起。
2. **独立对话 = 员工**：每个对话只负责一件事，对话之间互不共享记忆，都归用户管理。

### 两种混乱场景

1. **项目混乱**：没有分项目文件夹，十几个不同主题的对话挤在一个文件夹里。
2. **对话过载**：分了文件夹，但单个对话聊得太长、内容太多，出现变慢和记忆混杂。

### 对应解法

1. **抢救混乱项目**：不要在混乱项目里开新对话让它整理全部历史（消耗大量时间和 Token）。正确做法是新建项目文件夹 → 在原对话里发迁移指令，只提取需要的业务内容 → 迁移后写"记忆文件"记录进度和关键节点。
2. **处理过载对话**：不建议盲目压缩对话（会丢信息）。推荐开新对话，分两种情况：
   - 同一话题聊太多：让原对话总结记忆文件 → 新对话读取记忆文件接续。
   - 同一对话混了多件事：用拆分迁移指令，把不同业务拆到对应项目文件夹，每个文件夹单独写记忆文件。
3. **最省力技巧**：新建项目文件夹时，在第一个对话里输入一次"记忆规则指令"，之后系统自动记录项目关键信息、更新记忆文件，新对话开启后自动读取。

## 4. 我学到了什么

这条视频的核心价值不在具体指令，而在一套**Agent 使用卫生习惯**，和 Claude Code、Hermes 等工具的上下文管理理念完全一致：

- **隔离原则**：不同主题的工作物理隔离到不同目录，每个目录有自己的上下文文件。这和 Codex 官方的 AGENTS.md 分层机制（全局 → 项目 → 子目录）是对应的。
- **会话不共享记忆**：Codex 的会话（session）确实是独立的，不会自动继承其他会话的上下文。官方的持久化机制是 AGENTS.md 文件，不是会话间自动记忆。
- **记忆文件作为交接媒介**：让即将结束的会话把关键信息写成文件，新会话读取后接续——这是长任务跨会话接力的通用方法，在 Hermes（SOUL.md + memory）、Claude Code（CLAUDE.md）、Codex（AGENTS.md）中都是同一思路。
- **不要让一个会话扛所有事**：上下文窗口不是无限的吗？是的，但越长越贵、越慢、越容易丢关键信息。主动拆分比被动压缩更好。

## 5. 它是否可信，哪些需要验证

### 可信部分

- **项目文件夹隔离**：✅ Codex 确实以工作目录为项目边界，每个目录可以有自己的 AGENTS.md。
- **会话独立性**：✅ Codex 会话之间不共享上下文，官方持久化机制是 AGENTS.md 文件链。
- **AGENTS.md 作为项目记忆**：✅ 官方文档确认 Codex 启动时读取 AGENTS.md，支持全局（`~/.codex/AGENTS.md`）→ 项目根 → 当前目录的三级分层，合并上限 32 KiB。
- **拆分迁移比压缩更好**：✅ 这是上下文管理的通用最佳实践，不是 Codex 特有。

### 需要验证或存疑的部分

1. **"输入一次记忆规则指令，之后系统自动记录和更新记忆文件"**：⚠️ 这是视频最核心也最需要验证的 claim。根据官方文档和社区讨论（GitHub Discussion #12567），Codex **默认没有自动记忆功能**——AGENTS.md 是静态文件，需要手动维护。视频描述的"自动记录"可能是：
   - 一种 **prompt 驱动的工作流**（你在 AGENTS.md 或首次对话中写一条规则，要求 Agent 每次结束前更新某个文件），这在实践中可行，但不是 Codex 的内置功能；
   - 或者依赖第三方插件（如 Hindsight），但视频没有提及。
   - **结论**：这个技巧本身可行（让 Agent 养成写记忆文件的习惯），但"系统自动"的表述容易误导新手以为是内置功能。

2. **"迁移指令"**：⚠️ 视频提到用"迁移指令"从旧对话提取内容到新项目，但没有给出具体指令文本。这应该是 prompt 层面的操作（让 Agent 总结并写入文件），不是 Codex 的内置命令。

3. **"压缩对话会丢失关键信息"**：⚠️ 部分正确。Codex 的上下文管理确实会在接近窗口上限时影响质量，但"压缩"的具体机制（是截断？摘要？还是拒绝新输入？）需要查 Codex 源码或文档确认。笼统说"会丢信息"不够精确。

4. **项目文件夹和对话的关系**：⚠️ 视频用"公司/员工"类比，但 Codex CLI 的实际架构是"工作目录 + 会话"，一个目录下可以有多个会话。视频的类比是教学隐喻，不是 Codex 的术语。

## 6. 对个人能力有什么价值

对刚开始用 Codex / Claude Code / Hermes 等 Agent 工具的人，这套方法是最基本的"使用卫生"：

- **从一开始就分项目**：不要图省事把所有事情扔进一个目录。每个项目目录建一个 AGENTS.md（或 CLAUDE.md / SOUL.md），写清楚项目背景和规则。
- **会话是一次性的，文件是持久的**：任何需要跨会话保留的信息，都必须写入文件，不要指望 Agent "记住"。
- **会话变慢或变笨时，主动拆分**：让旧会话总结关键信息到文件，新会话从文件接力，比硬撑着继续聊效率更高。
- **建立"记忆文件"维护习惯**：每次重要工作完成后，花 1 分钟更新项目记忆文件（进度、关键决策、待办、坑）。

## 7. 对企业 AI 落地有什么价值

- **团队 Agent 使用规范**：可以把"分项目、写记忆文件、主动拆分会话"作为团队使用 Agent 工具的基本 SOP，降低新手踩坑率。
- **与现有 AGENTS.md 治理体系互补**：本条讲的是"怎么组织工作和会话"，已有的 `2026-07-26-codex-custom-instructions.md` 讲的是"AGENTS.md 里写什么规则"，两者互补。
- **适用于所有 Agent 工具**：这套方法不限于 Codex，Claude Code（CLAUDE.md）、Hermes（SOUL.md + memory）、Cursor（.cursorrules）都适用。

## 8. 可做的小实验

1. **验证"记忆规则指令"**：在一个 Codex 项目目录的 AGENTS.md 中写一条规则——"每次任务结束后，更新 `MEMORY.md` 文件，记录本次做了什么、关键决策、下一步"——然后连续开 3 个会话做不同任务，看 Agent 是否真的自动维护了这个文件。
2. **对比过载 vs. 拆分**：同一个任务序列，一种方式在一个会话里连续做 10 轮，另一种方式每 3-4 轮拆分一次并用记忆文件接力，对比输出质量和速度。
3. **验证 Codex 上下文耗尽时的行为**：故意让一个会话聊到接近窗口上限，观察 Codex 是截断、摘要还是报错。

## 9. 风险和边界

- **"自动记忆"容易误导**：视频说"系统会自动记录"，但 Codex 默认没有自动记忆功能。如果新手不验证就依赖，可能以为信息已保存但实际上丢失了。
- **记忆文件质量依赖维护**：无论手动还是 prompt 驱动，记忆文件如果只写不删，会积累过期结论和噪音，让 Agent 越用越笨。
- **Token 成本**：让 Agent 每次都读写记忆文件会增加 Token 消耗，需要平衡。
- **敏感信息泄露**：记忆文件如果自动生成，可能把 API Key、客户数据、内部路径写进去，需要定期检查。
- **视频为入门教学**：内容面向小白，用类比和口诀降低门槛，但精确度不够。不适合作为 Codex 功能的权威参考，只适合作为"使用习惯"的参考。

## 10. 视频原指令原文与修正

### 视频给出的"记忆指令原文"

> 请你先创建一个记忆文件。这个记忆文件的第一条规则是，当执行完一个对话任务时，识别对这个项目有用的关键信息并记录到记忆文件当中，以便于在后续执行任务时防止上下文遗忘；在该项目文件中开启新对话后，也能通过自动读取记忆文件，来获取这个项目的最新进度和关键信息。
>
> 使用说明：
> 1. 这个指令只需要在每个新建项目文件夹的第一个对话里输入一次即可，后续系统会自动跟踪项目进度、更新记忆文件，不用重复输入。
> 2. 记忆文件会自动记录项目的内容、进度和关键节点，新开启的对话会自动读取该文件，从根源避免上下文过载、记忆混乱的问题。

### 实际效果分析

这段指令在**当前会话**里是有效的：Agent 会按指令创建记忆文件并写入关键信息。

但它做不到"后续系统自动跟踪"和"新对话自动读取"，因为：

1. **在对话里输入的 prompt 只对当前会话生效**。新会话不继承对话历史——这正是视频自己在"基础概念"部分讲的"独立对话之间互不共享记忆"。在对话里输入一次指令，不等于配置了持久规则。
2. **Codex 默认只自动读取 AGENTS.md**（及其 fallback 文件名）。如果记忆文件叫 `MEMORY.md` 或其他名字，新会话不会主动读取，除非：
   - 配置了 `project_doc_fallback_filenames` 包含该文件名；
   - 或在 AGENTS.md 里写了"启动时读取 MEMORY.md"的规则。

### 修正方案

把指令逻辑写进项目根目录的 `AGENTS.md`，而不是在对话里输入一次：

```markdown
## 记忆维护规则

本项目使用 MEMORY.md 作为跨会话记忆文件。

### 写入规则
每次完成一个任务后，检查是否有对项目后续工作有用的关键信息。
如果有，更新 MEMORY.md，内容包括：
- 当前进度：本次做了什么，改了哪些文件
- 关键决策：为什么选这个方案，排除了什么
- 待办：下一步要做什么
- 踩坑记录：遇到的问题和解决方式

如果没有产生新的关键信息，不用更新。
每次更新覆盖旧内容，不要无限追加。
不要在 MEMORY.md 里写 API Key、密码、客户数据。

### 读取规则
每个新会话开始后，先读取 MEMORY.md，了解项目当前进度和关键信息，
再开始执行用户任务。
```

放在 AGENTS.md 里后，不需要在对话里输入。新会话启动时 Codex 自动读 AGENTS.md → 看到规则 → 读 MEMORY.md → 接上进度。这才是视频说的"输入一次、后续自动"的真实实现路径。

## 11. 当前结论

这条视频的价值是**使用习惯层面的入门教育**，不是 Codex 功能层面的技术资料。它讲的方法方向正确（隔离项目、拆分会话、记忆文件接力），与 Codex 官方 AGENTS.md 机制和通用 Agent 上下文管理最佳实践一致。

最需要注意的偏差是"系统自动记录记忆文件"的表述——视频给出的"记忆指令原文"在对话里输入只对当前会话生效，要做到跨会话自动维护和读取，必须把规则写进 AGENTS.md 而非对话 prompt。

与已有笔记 `2026-07-26-codex-custom-instructions.md`（AGENTS.md 写什么规则）互补：那条讲配置内容，这条讲使用习惯。两条合在一起，构成 Codex 项目治理的完整入门。
