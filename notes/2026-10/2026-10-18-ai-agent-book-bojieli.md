# 《深入理解 AI Agent：设计原理与工程实践》（李博杰开源书）

## 1. 这是什么

李博杰（Bojie Li，独立研究者，曾任 Pine AI 首席科学家）开源的 AI Agent 体系化教材：
**10 章正文 + 109 个配套实验 + 编译好的 PDF/EPUB + 15 种语言译本，全部免费**（Apache 2.0）。
在线版：https://bojieli.github.io/ai-agent-book/astro/ ；2026-10-18 核实时 54.7k star、6.2k fork，
曾上 GitHub Trending 日榜。姊妹篇《深入理解 AI Infra：量化分析与系统设计》6.7k star。

发现入口是抖音"Codex教程"的 2 分 55 秒推荐视频（136 赞/481 收藏）。短视频只起索引作用，
价值判断以仓库本体和作者主页为准。

## 2. 原始来源

- 仓库：https://github.com/bojieli/ai-agent-book （正文在 `book/`，实验在 `chapter1/`~`chapter10/`）
- 作者主页：https://01.me/whoami
- 姊妹篇：https://github.com/bojieli/ai-infra-book
- 作者背景（一手）：中科大+微软亚研院联合培养博士（2019），SIGCOMM/SOSP/NSDI/PLDI 多篇顶会，
  ACM 中国优博；现研究方向为 AI agent、个性化、LLM 系统、数据中心网络。
- 视频本体未获取口播内容，仅依据截图画面（GitHub 主页），不采信博主任何二手解读。

## 3. 核心结构（十章，围绕 Agent = LLM + 上下文 + 工具）

1. Agent 入门——**Harness 工程才是竞争力**
2. 上下文工程——KV Cache、提示工程、Agent Skills、上下文压缩
3. 用户记忆和知识库——跨会话记忆、RAG、结构化索引、知识图谱
4. 工具——MCP、感知/执行/协作三类工具、主动工具发现
5. Coding Agent 与通用 Agent——生产级 coding agent 全景
6. 交互扩展——异步/事件驱动、语音、Computer Use、机器人（2.0 新章）
7. Agent 评估——评估环境、指标、统计显著性、评估驱动选型
8. 模型后训练——SFT/RL 三阶段、工具调用内化、样本效率
9. Agent 持续进化——从轨迹中学习，更新知识/指令/程序/参数
10. 多 Agent 协作——上下文共享与隔离、Agent 社会

配套实验支持 Python 3.11–3.13，uv 安装，分章节 extras；实验代码由 coding agent 依据书稿生成，
仓库自带 `docs/EXPERIMENT_STATUS.md` 明确"克隆≠实验完成"，外部 22 个仓库固定 SHA 复现。

## 4. 我学到了什么

- 这本书的章节划分几乎就是我们这一年实际踩出来的 Agent 能力地图：上下文工程、记忆/知识库、
  MCP 工具、评估、持续进化、多 agent——J-Herm 体系（skill/memory/cron/成长复盘/子代理）
  全都能在其中找到对应章节，可作为**现有架构的理论校准标尺**，哪里是土办法、哪里有正式范式。
- 作者 FAQ 的立场与我们的工作方式同构："实验代码不需要逐行读懂，关键是架构和设计原则想清楚，
  让 AI 写代码跑测试，人负责最初设计和最终验收"——贵模型动脑、便宜模型动手有了公开背书。
- 第 7 章把评估当科研方法论而非工程收尾：没有评估集，长 prompt/harness 就不敢改、无法判断技术债。
  这正是我们目前 skill 迭代主要靠个案纠错、缺少回归评估集的短板。
- 作者 01.me 上的观点可直接引用：懂业务的人比纯技术的人更适合搭评估，关键是把人的标准提炼成
  rubrics——支持"业务侧定 rubric、实施侧自动化"的分工。
- 仓库工程化细节值得抄：GitHub Actions 每日自动构建多语种 PDF、star history 自动更新、
  EXPERIMENT_STATUS 门禁、外部依赖固定不可变 SHA。

## 5. 可信度与待验证

- 作者学术与工程背景一手可查（01.me/whoami、Google Scholar），非营销号拼凑；内容自 1.4 迭代到
  2.0（2026 年重组章节），维护活跃。可信度高。
- 109 个实验未逐一实测；README 自陈部分外部实验（训练、硬件、浏览器、多 agent）只固定了复现
  起点，未声称全部跑通——引用时不把"有实验代码"等同于"实验可复现"。
- 赞助商位（Krill AI，API 中转带邀请返利码）属于商业植入，API key 指南部分注意利益相关，
  选型时不因其推荐而偏向该中转商。
- 抖音博主"AI 入门看这份就够了"是夸张话术：本书要求中等 Python 能力且用过 coding 工具，
  对纯业务读者门槛不低，不是零基础科普。

## 6. 对个人/团队能力的价值

- 团队 AI 工程能力统一教材：比零散公众号/视频系统得多，中文正本免费，可直接作为实施组
  Agent 方向的共同读本和术语基准。
- 立刻可用的章节映射：第 2 章（上下文压缩/Skills）、第 3 章（记忆/RAG，对照我们的知识库分层）、
  第 4 章（MCP 工具治理）、第 7 章（给 J-Herm 建小评估集）、第 9 章（成长闭环的理论参照）。
- 第 7 章思考题路径：先为自己的 agent 建十几条任务的小评估集，围绕失败用例改进——
  可直接套到 CRM 答疑群的真实判例上。

## 7. 对企业 AI 落地的价值

- 给业务方/管理层解释"Agent 到底是什么、差在哪"时，这本开源书是中立、免费、可传阅的材料，
  比厂商白皮书更适合内部共识建设。
- 作者关于"数字员工"的量化框架（一个组长指挥 5 个 agent、长程任务时间窗口、decode token 成本）
  可用于 AI 落地 ROI 沟通：数字员工成本≈持续推理循环的输出 token 成本。
- 评估章节支撑我们对业务方的口径：高端问答必须有多系统取数+编排+压测，不能只演示 happy path。

## 8. 可做的小实验

- 下载 2.0 中文 PDF 入库，按章节做一张"书的能力地图 × J-Herm 现有机制"对照表
  （哪些已做、哪些是土办法、哪些空白），优先级最高的是第 7 章评估方法。
- 选第 7 章一个评估实验跑通（本地 Python 3.11+，用现有 ark-plan OpenAI 兼容端点，无需新 key），
  再用 CRM 答疑判例库构造 ≥10 条任务的小评估集雏形。
- 第 4 章 MCP 部分与我们 native-mcp/mcporter 实践对照，检查主动工具发现是否值得引入。
- 暂不做：第 8 章后训练实验（需 GPU 与训练数据，与当前工作距离远）。

## 9. 风险和边界

- 实验运行会产生模型 API 调用费用；部分实验要求 vLLM/硬件或外部仓库，投入前看每章 README 标注
  （✅可运行 / 📖复现 / 🚧设计）。
- 书是通用技术教材，不含国内企业合规、数据出境、私有化部署等议题，企业落地的安全边界仍需
  自行叠加。
- 译本为社区贡献可能滞后，引用内容以中文正本 `book/` 为准。

## 10. 当前结论

高价值、可信、零成本获取的体系化教材，且与我们实际架构高度同构，是近期打捞处资料里
"教材级"而非"线索级"的收获。建议作为实施组 Agent 方向基准读物；下一步先做能力地图对照
和第 7 章评估小实验，不急于通读全书。

## 11. 跟进记录（2026-10-20）

- 已下载 2.0 中文 PDF（11MB）；按第 2/3/4/7/9 章正本完成"书中范式 × 自有 Agent 体系"
  对照：上下文工程、记忆/RAG、MCP 工具、持续进化四部分基本同构，**唯一系统空白是第 7 章
  评估**——改 prompt/skill 没有回归门禁。
- 已实测复现实验 7-5（已知记忆的边界行为 prefix 评估）：11 合成用例 × 3 表示，在火山方舟
  OpenAI 兼容端点上对两个模型各跑 33 单元，零 API 错误，严格通过率 48%/55%；逐条复核后
  发现多数失分来自评分器枚举过严（同义决策标签互不认、记忆 ID 出现即判"使用"），
  语义合规率约 75–85%。真问题集中在"当前指令覆盖旧记忆不稳定"和"动作标签粒度"。
- 两个工程收获：①"最新指令优先"光靠系统提示词不够，需要自己的 prefix 回归集；
  ②记忆条目应带 scope/applies_when/confidence 结构化字段，评估器需配语义复核。
- 内部详细对照与结果存私有笔记（含端点与成本数据），不在此公开。
