# 紫微斗数开源排盘引擎（10k stars）：一个"传统知识工程化"样本

## 1. 这是什么

短视频截图推荐的 GitHub 项目。已追到本体并核实数据（2026-10-30 GitHub API 实查）：

- **Renhuai123/ziwei-doushu**：**10,093 stars / 2,006 forks**，TypeScript/Next.js，MIT，2026-05-01 创建，最近推送 2026-10-27，活跃。
  定位：基于倪海厦《天纪》体系的紫微斗数**排盘引擎**——完整排盘算法、四化系统、格局知识库、古籍原文数据。配套商业站 metisziwei.com（排盘+AI 解读+会员支付）。
- 同一波趋势下还有 **DestinyLinker/MingLi-Bench**（2,502 stars）：评测 LLM 在八字/紫微斗数上推理能力的 benchmark，160 道选择题，题源是 2022–2025"全球算命师大赛"，支持 OpenRouter/OpenAI/Anthropic/DeepSeek/豆包，区分"排盘推导"与"纯推理"两个环节（`--astro` 用 iztro 预算命盘）。
- 生态衍生物：多个 ziwei-doushu Claude Skill / Hermes Skill / MCP（taskyoooo、Linden-TR、jonhnsonzz 等，stars 都还很小），说明"把领域知识库蒸馏成 Agent Skill"的玩法正在这个圈子复制。

## 2. 原始来源

- 发现入口：群内截图（博主"香薰"短视频，字幕称"9.2k 星"，实际已过 10k；话题带 #办公就用dumate，疑似工具导流内容，数据略有夸大但项目真实）。
- 资料本体：https://github.com/Renhuai123/ziwei-doushu
- 数据集：Release v4.0-13d，674,976 张命盘（1950–2026 真实日期×12 时辰×男女）×13 维 = 877 万段解读，约 204 亿字，压缩 161MB / 解压 56.6GB，按 77 个年份分包。
- 关联：https://github.com/DestinyLinker/MingLi-Bench ；排盘库 iztro（https://github.com/SylarLong/iztro）。

## 3. 核心观点 / 核心能力

- 项目主张："**算法是公开的传统智慧，不应该被锁在围墙里**"。开源确定性的排盘算法和古籍数据，把价值留给解读深度、体验和运营——这是典型的"开源引擎+闭源服务"商业分层。
- 工程上值得看的做法：
  1. **确定性计算与 LLM 解读严格分层**：排盘是纯 TS 算法（含中国夏令时 `chinaDSTSpan`、城市经纬度表等脏活），LLM 只负责在结构化命盘之上做解读；
  2. **解读数据集先行**：先用规则/断语库批量生成 877 万段解读（13 维：事业、健康、婚姻等），再谈 AI——本质是把领域知识做成可检索/可训练的数据资产；
  3. **可核验的知识治理**：本轮更新删掉查无出处的"倪师原话"，每条引文标注集数和时间码，古籍引证 244→405 处且要求逐字可查；删除"不会发生的四化"断语、把两头堵的模糊断语改成按盘只显示成立分支；
  4. **开源边界写得极清楚**：代码 MIT、数据集 CC BY 4.0、古籍公版、倪师原话 CC BY-NC-SA（禁商用）；断语库、AI prompt、后端、支付全部闭源（db-analysis.ts 只是占位）。

## 4. 我学到了什么

- 这是"**玄学外壳、知识工程内核**"的项目：真正的看点不是算命，而是它演示了一个有师承体系、有经典文本、有确定性规则的垂直领域，如何被拆成「算法引擎 + 结构化知识库 + 批量解读数据集 + LLM 解读层 + Benchmark」五层。
- 它的知识治理动作（引文必须可回溯、删掉无法发生的规则分支、模糊断语按条件实例化）和我们做销售易判例库"问/境/判/据"的要求是同一个逻辑：**领域 AI 的可信度靠证据链，不靠话术**。
- MingLi-Bench 的设计也对：把"排对盘"和"解读对"分离评测，否则模型算错历法时你分不清是推导错还是推理错——对应企业场景就是"取数/计算对不对"与"判断/建议对不对"要分开压测。

## 5. 它是否可信，哪些需要验证

- 已核实：仓库真实存在、star 数、MIT 许可、数据集声明（API+README 实查，2026-10-30）。
- 未验证：
  - 56.6GB 数据集的实际质量只看了 README 自述，未抽样下载核验（压缩包仅 161MB 的压缩比、204 亿字规模合理但未独立复算）；
  - 排盘算法准确性未拿已知盘例对拍；
  - 短视频中的"wei-doushu"字样与实际仓库名 Renhuai123/ziwei-doushu 不完全一致，视频有二手引流痕迹，#dumate 标签暗示其可能是工具推广素材。
- 结论：项目本体可信且活跃；短视频是营销转述，数字轻度夸大。

## 6. 对个人能力有什么价值

- 当"领域知识结构化"的教学样本读：看一个非技术领域怎么被拆成数据模型、规则库、评测集。
- 可直接复用其方法论到我们的知识库建设：引文时间戳级回溯、规则分支按条件实例化、确定性层与生成层分离评测。

## 7. 对企业 AI 落地有什么价值

- 与英科业务无直接关系，**不建议任何业务试点**，B 主线雷达观察即可。
- 间接价值是架构参照：销售易/运维场景的智能问答同样应分层——确定性取数与计算工具化（他们的排盘引擎），开放解读才走 LLM（他们的 AI 解读层），且每层分别验收。这与"高端问答不是纯检索念稿、必带多系统取数+计算+编排"的既有口径一致，可作为对外讲架构时的通俗案例。
- 另一个信号：垂直领域"开源引擎+数据集+闭源服务+Skill/MCP 生态"的打包打法正在被小众领域快速复制，值得作为趋势观察。

## 8. 可做的小实验

- 无主动实验计划。如后续要研究"领域 benchmark 怎么搭"，可读 MingLi-Bench 的 data.json 与 iztro 预算命盘的 join 设计（半小时阅读量），不下载 56.6GB 数据集。

## 9. 风险和边界

- **版权分层**：倪师原话部分 CC BY-NC-SA 禁商用，数据集解读中引用的原话也不在数据授权内；如需引用只能用代码(MIT)/数据(CC BY 4.0)部分并署名。
- **内容合规**：命理类内容在国内属于敏感营销品类，企业环境不引入、不推广、不内嵌；仅作技术架构研究。
- **可信度**：命理结论本身无科学性，其"断语校正"提升的是与指定师承文本的一致性，不是客观正确性——勿把"引文可查"误读为"结论为真"。

## 10. 当前结论

短视频引流内容，但追到的本体是真实、活跃、star 数过万的高质量开源项目。价值不在玄学，在它完整示范了垂直领域知识工程化的五层架构和证据链治理；归入 B 主线雷达，学习其方法论，不做业务试点。
