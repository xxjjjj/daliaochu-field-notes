# 划卡共识投票 MVP：飞书群内 Roameo 式偏好采集实验

## 1. 这是什么

受 Roameo（AI 旅行规划，探探式划卡片聚合多人偏好）启发，验证"划卡模式"能否脱离旅游场景、用于企业内部的群体共识决策。MVP 不做独立 app，直接用飞书交互卡片承载：

- 机器人在群里发公告卡（主题 + "🎴 开始划"按钮）；
- 成员点按钮，机器人**私信**逐张发选项卡（🔥超想要 / ❤️还不错 / ❌不感冒）；
- 每张卡点完自动私发下一张，全程异步、独立、无需开会；
- 主持人喊停后出结果卡：按平均分排序，自动标注"全员心动 / 多数喜欢 / 两极分化 / 多数划走 / 无感"。

## 2. 原始来源

- 启发产品：Roameo（https://www.roameoai.com/，分析见 notes/2026-09/2026-09-02-roameo-ai-group-travel-planner.md）
- 设计依据：Fortune 2026-08 报道指出滑动手势正在从约会外溢到决策场景；通用产品 DecideAlready 已验证"任意问题 + 划卡投票"形态

## 3. 核心机制设计

- **私密性**：个人投票只有机器人可见，群里只出汇总。这是相对开会/群接龙的核心差异——消除话语权垄断和从众压力。
- **三档表态而非二选一**：🔥(2分)/❤️(1分)/❌(-1分)，强度加权避免"一个人最在意的被九个无所谓淹没"。
- **完赛者计分**：只统计划完全部选项的人，防止漏划偏差。
- **结果不强行平均**：单列"两极分化"标签——划卡最大价值之一是暴露"我们以为有共识其实没有"。

## 4. 实验状态

- 2026-09-02 第一局已在 8 人群聊中开局（主题：团队线下小聚形式，8 个选项），公告卡群内发送成功、私信发卡链路验证通过。
- 待观察：真实按钮回调后的完赛率、划卡耗时、结果认可度、是否引发二次讨论。

## 5. 可信与待验证

- 链路事实：飞书卡片按钮点击经 gateway 回调回流为可处理事件，发卡 OpenAPI 正常。
- 待验证：群成员是否真的觉得比接龙/投票好用；"两极分化"标签是否被认为有信息量；后续用于严肃场景（需求优先级）时卡片内容（AI 生成摘要）质量是否够用。

## 6. 能力价值

- 沉淀了一个"轻交互偏好采集"模式：任何候选池可枚举、判断偏感性、需要多人独立表态的场景都可复用（团建、选址、需求池排序、AI 产出批量验收/RLHF）。
- 边界已识别：不可逆、需定责留痕的决策（人事、预算、合同）不适合游戏化；候选卡片质量决定结果质量。

## 7. 下一步

- 跑完首局收集反馈；
- 若成立，扩展两个方向：① 候选卡片由 AI 从需求池/简历池自动生成；② 用于 AI 批量产出的人验反馈（划卡即 RLHF）。
