## 一句话主线

**当产出由 agent 生成，"质量"这个保证该放在哪一层？**

11 月这五张卡不是五个切面，是同一个问题的五个**位置**。按因果顺序排，它们是一条保证链：

```
输入（它记得对不对）
  → 存量（它倚仗的知识有没有过期）
    → 判定（什么算做对，谁说了算）
      → 环境（能不能让错的动作在结构上做不出来）
        → 改造（存量系统怎么分步迁过去）
```

## 三、这条链的真实优先级

从强的到弱的：**环境 > 判定 > 改造 > 输入 > 存量**。

环境之所以最强：它把"会不会做错"从概率问题变成结构问题 —— lint 拦掉、目录约束住、类型不允许，
agent 连错的机会都没有。这也是为什么 Lauren Tan 那批材料值得反复看：她的全部杠杆都在环境层，
而中文二创每次都把环境层拆散成"四招/七招"这类可执行动作，反而丢了这个结论。

存量之所以最弱还最危险：它是唯一一个**会自己变坏**的位置。其他四层不加不会退步，skill 库不加维护
一定腐化。

## 四、这条链缺的最后一环：可回退性

五张卡全在回答"怎么让 agent 做对"，**没有一张回答"做错了多久发现、发现了能不能撤回"**。
而这一环决定了前面五层能不能真的放开并行：

- 代码世界里，PR 能 revert，所以"自动合并"是可行选项 —— Lauren 敢让 agent 半夜自己合。
- 业务流程世界里，CRM 里一条客户归属写错，没有 revert。可验证性差 + 不可回退，两个短板叠加。

所以在真实业务系统里，正确的补法不是"把验证做得更狠"，而是**按可回退性给动作分级**：

1. 只读（查、汇总、比对）→ 可全自动，验证做够就行。
2. 可逆写（改草稿、改测试数据、改自己建的记录）→ 自动 + 留痕 + 事后抽查。
3. 不可逆写（客户归属、审批状态、权限、对外承诺）→ 必须人工确认，agent 只出建议和证据。

这一条比任何"四招/七招"都更能直接用在团队里，因为它是按动作性质切，不是按工具切。

- 团队带教：第 3 类动作（不可逆写）永远单独拎出来讲，不混在"提效"里说。

## 六、维护

- 每次有新卡命中这条主线，只改第二节表格和第三节优先级，不重写全文。
